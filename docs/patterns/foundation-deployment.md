# One-environment AWS foundation

The foundation CDK app defines a single Wander demo environment. Its VPC has two explicitly supplied availability zones, public load balancer subnets, private service subnets, and one NAT gateway. An internet-facing HTTPS ALB is reserved for GraphQL; a separate internal HTTP ALB is reserved for REST. The shared ECS cluster, on-demand DynamoDB trip table, Cognito user pool and public PKCE client, two ECR repositories, private static UI bucket, and encrypted API log group are created here. API services, CloudFront, and deployment orchestration are separate later stacks.

Every cross-stack output has a `/wander/<environment>/v1/` SSM Parameter Store path. Service stacks should consume these names with deploy-time references such as `StringParameter.valueForStringParameter`, not account lookups during synthesis. The deployment app validates account, region, two AZ names, HTTPS site origin, matching ACM certificate ARN, Cognito domain prefix, and exact deployment principal ARN. Choose AZs confirmed available in the target account. The app supplies those AZs as explicit CDK context, so synth needs no AWS credentials. No secret value is created or embedded in a template. GraphQL's task execution role can read the existing named provider secrets; the REST task role alone can access the trip table. Separate REST and GraphQL execution roles, task roles, and a deployment trust role prevent accidental credential sharing. The deployment role has no action policy yet; later service/deploy stacks must add only the required actions before it can be used.

The private UI bucket blocks public access and uses S3-managed encryption. DynamoDB uses AWS-managed encryption, point-in-time recovery, and retain-on-delete. API logs use a rotating KMS key and expire after 14 days; the KMS key, Cognito pool, bucket, and table retain on stack deletion. Retained resources must be reviewed and removed manually after exports and backups. A `cdk destroy` is not a full teardown. The NAT gateway, two ALBs, KMS key, DynamoDB recovery, logs, storage, and eventual Fargate/CloudFront can incur charges even when nobody uses the demo. Check current regional pricing before deployment. One NAT gateway also means one AZ's egress path is a demo-level availability trade-off.

For an offline dry run, from `platform-cdk/` install pinned dependencies with `pnpm install --frozen-lockfile`, copy `.env.example` to `.env`, replace the sample account, certificate, principal, origin, AZs, and Cognito prefix with valid formats, then run `pnpm typecheck`, `pnpm test`, and `pnpm infra:synth`. The committed test fixture uses fake IDs and no AWS credentials. Synthesis asserts private data resources, IAM separation, versioned parameter paths, and no secret values. It does not prove the named secrets exist or that a cloud deployment succeeds. The CDK CLI is a project dependency; no global CLI or account is needed for synth.
