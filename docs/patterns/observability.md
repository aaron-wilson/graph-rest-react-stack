# API telemetry

Both APIs start OpenTelemetry before importing application code. `TELEMETRY_MODE=off` is the default and creates no exporter or outbound call. `TELEMETRY_MODE=otlp` requires `OTEL_EXPORTER_OTLP_ENDPOINT`, an OTLP HTTP collector origin. The APIs export traces, duration metrics, and structured event logs. GraphQL passes W3C `traceparent` to REST. The browser creates a fresh trace context for GraphQL HTTP and SSE requests without embedding identity or itinerary text. Provider spans carry only capability names; log fields are allowlisted and trace correlated. Export batches and queues are bounded.

HTTP request spans leave expected client outcomes (4xx) UNSET and exclude them from `wander.operation.errors`. REST classifies the normalized response: each 5xx marks `http.rest` ERROR and increments the counter once. Health requests stay UNSET. GraphQL marks `http.graph` ERROR when Yoga rejects or its error hook classifies an internal resolver failure, including failures returned with HTTP 200; semantic client errors stay UNSET. Resolver failures count under `graphql`, rejected Yoga requests under `http.graph`. Neither path attaches exception messages to spans. Graph request spans end on response finish or disconnect, once.

For local inspection, run `TELEMETRY_MODE=otlp OTEL_EXPORTER_OTLP_ENDPOINT=http://collector:4318 docker compose --profile telemetry up --build -d` from the hub. Use the app, then open Jaeger at `http://localhost:16686` to find `wander-graph` and `wander-rest` traces. `docker compose logs collector` shows basic metric and log export counts. The collector applies a memory limiter and bounded batches. This path needs Docker, but no account.

New Relic forwarding is optional. With a New Relic account, supply `NEW_RELIC_LICENSE_KEY` to the collector process and set `NEW_RELIC_OTLP_ENDPOINT` if outside the US region; point APIs at `http://collector-newrelic:4318` with `TELEMETRY_MODE=otlp`, then start the `newrelic` profile. The collector adds the required `api-key` header. The key stays out of application containers and business code. Use `telemetry/newrelic-dashboard.json` as a dashboard import template: replace every `"accountId": 0` with your New Relic account ID, then go to Dashboards → Import dashboard → paste JSON, select the account and permissions, and save ([dashboard import instructions](https://docs.newrelic.com/docs/query-your-data/explore-query-data/dashboards/dashboards-charts-import-export-data/)). The template includes one page with three configured widgets for operation latency, error logs and provider duration. Its error query uses `severity.text`, the attribute New Relic maps from OTLP `severity_text` ([OTel log field mapping](https://docs.newrelic.com/docs/opentelemetry/best-practices/opentelemetry-best-practices-logs/)). Run `node --test scripts/check-newrelic-dashboard.test.mjs` from the hub for offline structure and query checks; these do not prove a live import or metric behavior. No New Relic account, dashboard, alert, or billing behavior has been live verified.

The local viewer is for traces. Metrics and logs are visible through collector debug output; this is a demonstration path, not a retained production store. A production collector should send them to a configured backend and apply retention and access controls there.
