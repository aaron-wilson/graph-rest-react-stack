# REST authorization and API contract

Wander's REST service owns trip data. Every private route authenticates the caller before reading or changing a trip, and every store call includes the principal's owner ID. In `APP_MODE=demo`, a request sends `Authorization: Bearer demo` and receives the fixed `demo` principal. This makes the complete local flow work without an account. `APP_MODE=live` requires a Cognito user pool and client ID; its verifier checks the access token's signature, issuer, client, token use and expiry. Live composition does not select demo auth.

For example, a client creates a trip with `POST /trips` and the demo bearer token, then updates it with `PATCH /trips/{id}` and a body containing `version` plus `changes`. Each edit expects the stored version and returns a conflict on a stale version. Day, activity, preferences, pin and swap routes follow the same rule. `POST /trips/batch` accepts up to 100 IDs and returns only trips owned by the caller in input order; GraphQL uses it for request-local batching.

Public links are a separate read path: `POST /trips/{id}/share` creates a random token that expires after seven days, and `GET /shared/{ownerId}/{tripId}/{token}` returns only ID, city, days and update time. `DELETE /trips/{id}/share` revokes the token immediately. The public path deliberately does not expose preferences or owner fields in its response. A link includes owner and trip IDs so the store can read by key without a token index; the random token is the bearer secret.

The service reads JSON bodies up to a 64 KiB cap and validates them with Zod. Its process-local limit defaults to 120 requests per minute: private requests use the verified principal, while public reads and failed authentication use the client address supplied by Bun. When Bun cannot identify an address, those requests share one fallback bucket. Forwarded address headers are ignored. A full limiter rejects new callers until a window expires. The service also sets explicit CORS origin/method/header settings and response headers that prevent MIME sniffing and referrer disclosure. A multi-instance deployment needs a shared rate limiter and trusted edge enforcement.

`GET /openapi.json` serves the schema-derived document from `rest-api/src/openapi.ts`; `GET /docs` serves local Swagger UI assets. Regenerate the checked-in snapshot with `bun run spec:snapshot` in `rest-api`. `bun run test` verifies real HTTP behavior, authorization, share expiry/revocation, route validation, and runtime/snapshot equality. The current contract is designed for the local demo and future GraphQL client; account setup and live Cognito calls are separate activation steps.
