# Static UI on a private S3 origin

The UI CDK app serves the actual Next `trailingSlash` export through CloudFront and a signed S3 origin access control. It imports the foundation bucket by deploy-time SSM reference and owns the entire bucket policy: deny insecure transport and allow CloudFront `s3:GetObject` only for this distribution's source ARN. Foundation owns the bucket and public-access block, while UI owns its policy; there must be one policy writer. Deploy the updated foundation before the UI stack to transfer policy ownership. No public website endpoint, Next server, Lambda or Step Functions is created. The existing site-host certificate must be in us-east-1 for CloudFront, even when the rest of the environment is elsewhere. The regional API ALB certificate is separate. Point the owned site DNS name at the resulting distribution after an explicit deployment.

The viewer-request function rewrites only the six known exported page paths to `index.html`. A missing trailing slash receives a redirect that preserves the query string; callback codes and share query parameters remain browser-visible when HTML is fetched. Missing routes and assets are not mapped to the home page. S3 missing-object 403 and 404 responses become 404s using the export's `404.html`. HTML and other mutable files cache for 60 seconds by default (0–300 seconds), without cookies or query strings in the cache key. Hashed `_next/static/*` assets cache for one year. The CDN has no API proxy behavior; authenticated GraphQL and SSE use the separate HTTPS API endpoint, whose configured CORS origin must exactly match the site origin.

Use the shared installed hub CDK toolchain and the UI's real `infra:typecheck`, `infra:test` and `infra:synth` scripts with explicit `infra/.env.example` inputs. `UI_CERTIFICATE_ARN` is an existing matching-account ACM certificate, not a credential. Synthesis is offline with fake IDs, no lookups and no automatic env-file load. `UI_ASSET_REVISION` is the full UI Git SHA. Run `node scripts/build-static.mjs` with the intended `NEXT_PUBLIC_*` environment: `NEXT_PUBLIC_APP_MODE=live`, HTTPS `NEXT_PUBLIC_GRAPHQL_URL`, Cognito domain, public client ID, issuer and `/auth/callback/` redirect URI. The existing root env example describes these public fields. The build writes `out/deployment.json` with revision and public deployment identity. Changing container/runtime environment later cannot change built JavaScript; rebuild to change any public URL, auth setting or monitoring configuration. Credentials and client secrets never belong in these fields.

Publication defaults to printing commands: `UI_BUCKET_NAME`, `UI_DISTRIBUTION_ID`, `UI_ASSET_REVISION` and optionally `STATIC_ARTIFACT_DIR` select the reviewed artifact. `node scripts/publish-static.mjs --execute` is the explicit account-writing operation. It checks the manifest revision and required route files, uploads hashed assets first with immutable cache control, then other files, then HTML, and invalidates page paths and mutable route payloads. It never deletes old hashed assets. Keep the previous complete export for rollback and republish it with its own manifest revision; do not rebuild an old source against today's configuration and call it the same artifact. Retention of old hashes protects old pages during rollout, but mutable Next route payloads do not promise an atomic site-wide transition. Remove stale hashes only after a separately reviewed retention period.

Offline tests exercise known-route rewrites, query preservation, missing-asset behavior, private OAC policy, cache settings and publication order. `node scripts/check-static.mjs` starts the actual export server on loopback and checks direct page loads, docs, callback/share query paths and missing assets. Cloud DNS, certificate coverage, OAC delivery, Cognito redirects and account publication remain live-unverified owner checks.
