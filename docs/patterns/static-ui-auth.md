# Static UI authentication

The static Wander UI has two build modes. Demo mode starts with the `demo` identity and sends `Authorization: Bearer demo` to private GraphQL and itinerary stream requests. Live mode starts anonymous and uses Cognito managed login with Authorization Code + PKCE. The Cognito app client must be public, have no client secret, allow the authorization code grant and `openid` scope, and register the exact deployed `/auth/callback/` URL. The static export includes that route; there are no API routes, server actions, request-time server code, or browser-embedded client secrets.

Set public build values `NEXT_PUBLIC_APP_MODE=live`, `NEXT_PUBLIC_GRAPHQL_URL`, `NEXT_PUBLIC_COGNITO_DOMAIN`, `NEXT_PUBLIC_COGNITO_CLIENT_ID`, `NEXT_PUBLIC_COGNITO_ISSUER`, and `NEXT_PUBLIC_AUTH_REDIRECT_URI`. The login URL carries a random state and nonce plus a SHA-256 PKCE challenge. Only the one-time state, nonce, verifier, timestamp, and redirect URL enter `sessionStorage`; the transaction expires after ten minutes and is removed when the callback is handled. The callback verifies its configured origin and path, state, nonce, issuer, client ID, token use, subject, and expiry. The UI does not cryptographically validate JWT signatures: GraphQL and REST independently verify access tokens against Cognito before authorizing private operations.

The access token stays in React memory. Sign-out clears it and creates a new urql client so another identity cannot receive cached trip data. Reloading requires login again. GraphQL HTTP and fetch-based SSE use bearer headers, never token query parameters. Anonymous shared-trip reads remain available; all private GraphQL operations and REST routes enforce ownership regardless of what the UI displays. API live mode rejects demo credentials.

Verify in `react-ui` with `pnpm test`, `pnpm typecheck`, `pnpm lint`, `pnpm format:check`, `pnpm codegen:check`, `pnpm schema:check`, `pnpm build`, and `pnpm test:e2e`. Tests use deterministic local token fixtures; no Cognito account or network login is required. Run the GraphQL and REST auth suites in their repositories to verify their independent live-mode rejection and ownership checks.
